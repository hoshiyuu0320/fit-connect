# photos-custom — オーナー提供のラベル付き料理写真

日本の実際の食事写真で A/B を行うためのデータセットです。特に **コンビニ食品** はパッケージの
**栄養成分表示（熱量・たんぱく質・脂質・炭水化物）** がそのまま正解値になるので、最も信頼できる評価データになります。

> このディレクトリで Git に入るのは `README.md` と `labels.example.csv` だけです。
> `raw/`（元写真）、`images/`（前処理済み）、`labels.csv`、`cases.json` は **ローカル専用** で、コミットされません（`.gitignore` 済み）。

## 1. 撮り方

- アプリで記録するときと同じように、**スマートフォンのカメラで普通に撮る**（真上〜斜め 45° 程度、料理全体が入るように）。
- **栄養成分表示・商品名・値札・レシートが写らないようにする。** 写っているとモデルが数字を読めてしまい「推定」の評価にならない。
  フタやパッケージ裏の表示は、撮影後に別途メモする（または表示面を裏返して撮る／器に移して撮る）。
- 1 ケースにつき写真は **1〜3 枚**（本番の上限も 3 枚）。別角度や別皿を足す場合は同じ食事の写真だけにする。
- 顔・人物・住所・名札など、食事以外の個人情報が写り込まないようにする。
- 「食事ではない写真」（風景・ペット・ミーム等）も数枚あると「正しく拒否できるか」を測れる（下記 `is_meal=false`）。
- 写真はそのまま `raw/` に置く（HEIC は不可。iPhone は「設定 > カメラ > フォーマット > 互換性優先」で JPEG にするか、書き出し時に JPEG/PNG に変換）。
  取り込み時にアプリと同じ前処理（1920×1080 の枠に縮小・JPEG 品質 80）がかかり、**位置情報などのメタデータは削除** されます。

## 2. ラベルの付け方（`labels.csv`）

`labels.example.csv` をコピーして `labels.csv` を作り、1 行 = 1 食事で書きます。

| 列 | 内容 |
| --- | --- |
| `id` | 英数字・`_`・`-` のみ。重複不可（例: `conv-001`） |
| `files` | `raw/` からの相対パス。複数枚は `;` 区切りで最大 3 枚（例: `IMG_0002.jpg;IMG_0003.jpg`） |
| `meal_type` | `breakfast` / `lunch` / `dinner` / `snack` |
| `content` | アプリで入力する補足テキスト。無ければ空（本番では「(なし、画像のみ)」になる）。カンマを含むなら `"..."` で囲む |
| `calories`, `protein_g`, `fat_g`, `carbs_g` | **実際に食べた量** の合計（kcal / g）。4 つとも空なら「採点しない」ケース |
| `note` | 自由記述（出典・按分の根拠など）。cases.json に `note` として残る |
| `is_meal`（任意列） | `false` にすると「食事ではない画像」＝正解は foods 空（EMPTY）。栄養値は空にする |

栄養成分表示から数値を作るときの注意:

- 表示が **「1 包装あたり」** ならそのまま。**「100 g あたり」** なら内容量で換算する。
- 炭水化物が **糖質と食物繊維に分かれている** 場合は **炭水化物 = 糖質 + 食物繊維**。
- 複数商品を一緒に食べたなら合計する。一部だけ食べたなら食べた割合で按分し、`note` に書く。
- ドレッシング・ソース等が別添なら、使った分を含める（使わなかったなら含めない）。
- 小数は四捨五入で整数に（取り込み時にも丸めます）。
- 手料理などで正解値が分からない写真は、栄養値を空にしておくと「採点しない」ケースになる（EMPTY 判定やレイテンシの比較には使われる）。

## 3. 取り込み

```bash
cd evals/meal-estimation
cp datasets/photos-custom/labels.example.csv datasets/photos-custom/labels.csv   # 初回のみ。中身を書き換える
npm run import:custom      # raw/ → images/ に前処理、cases.json を生成
npm run estimate           # 費用の見積り（生成 API は呼ばない）
```

`labels.csv` にエラー（列不足・ファイルが無い・栄養値が一部だけ空など）があると、全件を列挙して止まり、`cases.json` は書き換えません。

## 4. プライバシー

- `raw/`・`images/`・`labels.csv`・`cases.json` は **このマシンの中だけ** に置きます（Git に入らない設定済み）。共有が必要な場合は個別に判断してください。
- A/B 実行（`npm run run -- --yes`）では `images/` の画像が **Anthropic API に送信** されます（本番アプリと同じ扱い）。送ってよい写真だけを入れてください。
- 実行結果（`runs/<日時>/raw.jsonl`）にはモデルの回答テキストが残ります（画像そのものは保存しません）。`runs/` も Git には入りません。
